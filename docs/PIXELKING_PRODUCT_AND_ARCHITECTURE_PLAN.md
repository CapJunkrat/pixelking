## 1. 产品核心定位

PixelKing 是一款手机竖屏优先、以短局为主的像素风国际象棋 Roguelike。

核心体验优先级已经确定为：

1. **融合构筑是第一核心。**
2. 棋盘战术为构筑提供验证场景。
3. 路线选择、奖励、商店、事件和遗物共同提供风险收益抉择。
4. AI 暂时保持简单贪心，不追求高强度棋力；目标是让玩家体验构筑，而不是被强 AI 压制。

目标常规 Run 时长为 **20–30 分钟**。玩家应当在数轮尝试内有较高机会完成首次通关，而不是面对高难度棋类挑战。

未来可以加入递增挑战等级，但不进入首个纵切版本。长期挑战主要先由无尽模式承担。

## 2. 已确认的完整游戏流程

### 2.1 主流程

点击 `New Journey` 后，不再直接进入当前战斗场景，而是进入以下流程：

```text
New Journey
  ↓
如已有活动 Run：确认是否覆盖
  ↓
输入或随机生成 Run Seed
  ↓
三轮开局三选一选秀
  ↓
生成纵向分叉路线地图
  ↓
选择节点
  ↓
非战斗整备 / 战前自由部署
  ↓
战斗
  ↓
奖励三选一 / 商店 / 事件 / 休息
  ↓
返回路线地图并进入下一层
  ↓
最终 Boss
  ↓
Run 结算、图鉴更新、解锁无尽模式
```

### 2.2 双层可玩里程碑

后续开发拆成两道门，避免内容生产和美术精修阻塞完整 Run：

**里程碑一：最小完整 Run 闭环。** 使用现有素材和占位数据打通：

- 三轮选秀
- 路线地图
- 战前部署
- 普通与精英战斗
- 奖励与融合
- 战败牺牲与重试
- 商店、事件、休息与遗物
- 最终 Boss
- Run 结算
- Continue 自动存档恢复

闭环验收内容至少包括：约 8 种棋子、2 个融合产物、4 个遗物、4 个随机事件和 1 个 Boss。

**里程碑二：发布候选。** 在核心循环测试通过并完成至少一次稳定人工通关后，进入阶段 K，补齐约 12 种棋子、5 个融合产物、10 个遗物、8 个随机事件和 1 个 Boss，并完成静态视觉与统一 UI 精修。

系统和闭环优先，允许使用文本、色块、现有素材和占位数据；正式美术与复杂演出不得阻塞里程碑一。

## 3. 常规 Run 与无尽模式

### 3.1 常规 Run

- 单区域，约 **6–8 层**。
- 每层通常提供 **2–3 个可选节点**。
- 使用固定骨架、随机节点内容的纵向分叉地图。
- 玩家从地图底部向上推进，节点选择后不能回退。
- 地图信息完整公开，玩家可提前看到节点类型、敌人倾向和奖励类别。
- 地图至少保证：
  - 1 个精英节点
  - 1 个商店
  - 1 个休息节点
  - 最终 Boss
- 普通战斗与随机事件填充其余节点。

### 3.2 无尽模式

- 初始锁定。
- 首次完成常规 Run 后解锁。
- 无尽模式是独立新 Run，重新进行三轮开局选秀，不继承最近通关阵容。
- 核心目标是检验阵容与融合构筑能够坚持多少关。
- 敌人持续增强。
- 首版无需同时实现复杂排行榜，但 Seed 与确定性架构应为未来挑战模式预留基础。

## 4. 路线节点设计

首版节点类型全部需要在数据层预留：

1. **普通战斗**
   - 主要推进节点。
   - 胜利后提供基础金币和三选一奖励。

2. **精英战斗**
   - 更高风险。
   - 是遗物的重要来源之一。
   - 奖励稀有度高于普通战斗。

3. **商店**
   - 使用战斗和节点奖励获得的金币。
   - 支持付费刷新。
   - 可出售：
	 - 棋子
	 - 当前阵容满足条件的融合图纸
	 - 一次性道具
	 - 棋子保护/移除服务
	 - 休息类服务
   - 玩家只能在商店主动出售已有棋子、遗物或道具。

4. **随机事件**
   - 风格以风险收益抉择为主。
   - 使用短文本包装机制选择。
   - 可以影响金币、棋子、失败机会、遗物、道具或路线状态。

5. **休息/修整**
   - 每次提供三选一服务。
   - 服务池可包括：恢复、保护、金币或其他整备效果。
   - “保护棋子”默认抵消下一次牺牲：受保护棋不进入下一次战败候选，触发后保护消失。

6. **Boss**
   - 路线终点。
   - 使用特殊棋盘或特殊目标。
   - 击败后立即结算常规 Run。

## 5. 开局选秀与稀有度

### 5.1 开局选秀

- 每个新 Run 从标准国王开始。
- 连续进行 **3 轮三选一**。
- 每轮选择一枚棋子，全部加入初始构筑。
- 每轮至少保证一枚 **稀有或更高** 的强力棋子。
- 开局选秀池只出现普通与稀有基础棋：
  - 不出现融合产物。
  - 史诗与传说留给路线成长。
- 每次 Run 的初始构筑应不同。

### 5.2 稀有度

采用四档稀有度：

1. 普通
2. 稀有
3. 史诗
4. 传说

稀有度用于统一影响：

- 棋子基础强度
- 奖励池
- 商店价格
- 节点掉落
- 图鉴表现
- 融合产物定位

奖励稀有度主要由 **节点类型与路线层数** 决定。越后期、精英和 Boss 的奖励池越好。

## 6. 阵容、仓库与部署

### 6.1 容量

- 可上场的非国王棋子容量：**5**。
- 国王不占上述 5 个挑战者上场位，并且必须上场；因此完整阵容最多为“国王 + 5 枚非王棋”。
- 仓库容量：**5**。
- 上场与仓库分离。
- 所有非战斗界面都可以打开阵容管理，调整上场与仓库。

### 6.2 获得棋子

- 普通棋子奖励默认进入仓库。
- 仓库已满时，玩家必须当场替换一枚已有棋子或放弃新棋。
- 不能依靠无限候补区规避容量限制。

### 6.3 战前部署

- 每场战斗前进入部署阶段。
- 玩家可以在己方两行内自由部署上场棋子。
- 国王也可以放置在己方两行任意合法格。
- 玩家可以完整看到敌方阵容与初始位置，再决定自己的部署。
- 玩家默认先手，但遗物未来可以改变先手规则。
- 普通战使用标准 8×8 棋盘。
- Boss 可以使用特殊棋盘尺寸或格子规则。

## 7. 战斗胜负、战败与重试

### 7.1 普通与精英战胜利

- 普通战和精英战继续采用快速终局规则：**敌方只剩国王时玩家获胜**。
- 不要求把残局继续走到标准将死。
- 当前自定义王车易位继续保留：国王与未移动的己方车交换位置；这不是标准国际象棋易位。

### 7.2 Boss 胜利目标

Boss 允许覆盖普通胜利目标。

每个 Boss 通常组合 1–2 种机制，而不是要求单个 Boss 包含全部机制：

- 多阶段
- 击破部件
- 限定回合击杀
- 占领关键格

Boss 目标、阶段和特殊棋盘应数据驱动；复杂 Boss 可以通过专属目标脚本扩展。

### 7.3 三次战败规则

- 整轮 Run 累计最多失败 3 次。
- 第 1、2 次战败：进入三选一牺牲流程，然后重试同一遭遇。
- 第 3 次战败：Run 直接结束，不再进行无意义的牺牲选择。
- 如果战败时没有可牺牲的非国王棋子，即使还未达到第三次，Run 也直接结束。

### 7.4 牺牲流程

- 候选池来自玩家拥有的全部非国王棋子，包括上场与仓库。
- 融合棋也可能成为牺牲候选。
- 系统随机提供三枚候选，玩家选择牺牲其中一枚。
- 受到保护的棋子不进入下一次候选池。
- 牺牲后：
  - 敌我战斗局面完全重置。
  - 敌方恢复同一遭遇模板。
  - 玩家使用损失后的阵容重新部署。
  - 同一遭遇的奖励不会因为失败而降级。

## 8. 融合系统

融合构筑是项目的第一核心系统。

### 8.1 固定配方

- 融合采用预先设计的固定配方。
- 配方示例：A + B + C → X。
- 玩家必须实际拥有配方所需的全部素材，配方图纸才允许进入掉落池或商店。
- 如果玩家只有 A 和 B，则要求 A+B+C 的图纸不能出现。
- 素材中的同类型实例在首版完全等价，不考虑实例强化差异。

### 8.2 融合执行

- 图纸出现在奖励三选一或商店中。
- 玩家选中图纸后，先显示完整预览：
  - 将消耗哪些棋子
  - 生成什么融合棋
  - 产物走法、被动与稀有度
  - 阵容和容量变化
- 玩家确认后：
  - 所有素材被消耗。
  - 生成一枚独立融合棋。
  - 融合棋默认进入仓库，之后重新编队。
- 玩家取消确认时返回原三选一，仍可选择其他奖励。
- 商店图纸使用同一套预览、确认与自动融合流程；确认后才扣除金币。

### 8.3 多级融合

- 融合产物可以继续作为更高阶配方的素材。
- 形成明确的融合树。
- 每个融合产物都是预先设计好的独立 `PieceDef`：
  - 稳定 ID
  - 专属名称
  - 专属美术
  - 稀有度
  - 移动规则
  - 被动能力

### 8.4 国王融合

- 初始始终是标准国王。
- 国王可以参与固定配方融合。
- 王融合产物必须继承唯一的 `King` 身份与失败条件。
- 原国王与素材被消耗，产物成为新的唯一追踪国王。
- 王融合产物强制处于上场阵容。
- 王融合后仍使用统一的将军与失败规则。
- 融合王可以继续参与更高阶王融合。
- 合格的王融合图纸与普通图纸一样进入随机奖励池，但可以设置更高稀有度。

## 9. 奖励、金币与商店

### 9.1 战斗奖励

- 战斗胜利后主要使用三选一奖励。
- 候选可包含：
  - 棋子
  - 当前满足条件的融合图纸
  - 金币
  - 道具
  - 遗物（根据节点来源决定）
- 金币主要来自节点奖励与事件，不依赖战斗中的吃子数。

### 9.2 商店

- 使用金币购买。
- 支持付费刷新。
- 商品生成必须使用独立 RNG 流并保存候选，防止退出游戏刷新商品。
- 玩家可以在商店出售已有内容。
- 融合图纸必须经过资格过滤，只展示当前阵容可立即融合的配方。

### 9.3 事务式选择

为了防止通过强退刷奖励：

1. 先根据 Seed 生成并保存奖励、事件或商店候选。
2. 再展示给玩家。
3. 玩家提交选择后，以事务形式更新 RunState 并保存。

## 10. 遗物与一次性道具

### 10.1 共享六槽

- 遗物和一次性道具共用 **6 个挑战者槽位**。
- 这与当前工程中 persistent/consumable 共用栏位的方向一致。
- 遗物永久占据槽位，直到玩家主动替换或移除。
- 一次性道具使用后消失并释放槽位。
- 满槽获得新内容时，玩家选择替换已有内容或放弃新内容。
- 被替换的遗物永久销毁，不自动返还金币。

### 10.2 遗物

- 首个纵切也需要完整的遗物系统，而不是完全延期。
- 首批遗物以改变战斗规则为主。
- 遗物来源包括精英、Boss、商店和事件，不同来源可使用不同池。
- 相同遗物不可重复获得，已拥有遗物从候选池移除。
- 遗物与棋子被动共用统一战斗事件与效果队列。

### 10.3 一次性道具

- 在己方走棋前使用。
- 每回合最多使用一个。
- 使用道具不消耗本回合正常走棋机会。
- 道具效果也通过统一命令/事件管线执行。

## 11. 特殊棋子、被动与效果队列

### 11.1 能力方向

特殊棋子以被动能力为主，但效果系统必须具备足够通用性，允许未来能力：

- 移动或交换其他棋子
- 召唤或复制棋子
- 改变格子状态
- 修改移动规则
- 在移动前后触发
- 在吃子与被吃时触发
- 在回合开始/结束触发
- 在将军或濒死状态触发
- 提供邻接或站位持续效果

### 11.2 基础行动经济

- 仍保持一回合移动一枚棋子一次。
- 道具是走棋前的额外操作。
- 首版不引入多行动点系统。

### 11.3 效果结算

战斗阶段建议明确拆分为：

```text
部署
→ 玩家道具窗口
→ 玩家走棋
→ 效果队列结算
→ 敌方行动
→ 效果队列结算
→ 终局检查
```

结算规则：

1. 当前行动方的触发优先。
2. 同方效果按以下顺序稳定排序：
   - 效果优先级
   - 棋盘位置
   - 实例 ID
3. 允许完整死亡连锁。
4. 必须提供防无限循环机制，例如最大事件数、同来源重复保护或明确错误终止。
5. 整个效果队列结算完成后，再检查将军、孤王和胜负。

### 11.4 统一 BattleEvent

每次行动应生成一串稳定、可记录的 `BattleEvent`，由不同系统共同消费：

- 规则状态更新
- 动画播放器
- 简洁战斗日志
- 自动化测试
- 未来回放与 Bug 复现

表现与逻辑必须分离：

- 逻辑先生成确定性事件序列。
- 表现层逐个消费事件，但首版只承诺静态棋子、程序化 Tween、格子/UI 提示、轻量通用特效与音效。
- 不为棋子制作逐帧动画、cut-in、推镜或逐 PieceDef 专属动作。
- 玩家可以加速或跳过表现。
- UI 与 Tween 不能反向决定规则结果。

## 12. AI 与敌方遭遇

- 当前贪心 AI 暂时保留。
- 不实现 Minimax，避免敌人过强。
- 后续只修复明显错误或让 AI 理解新增合法行动，不主动大幅提高棋力。
- 敌方强度使用分层遭遇模板：每一层从对应强度池中抽取敌方阵容。
- 普通战以模板为主，不根据玩家战力进行强制动态追平。
- AI 同分决策若参与可复现要求，应从战斗独立 RNG 流中选择。

## 13. Seed、随机流与可复现性

- 玩家可以查看并手动输入 Run Seed。
- 相同 Seed 至少必须复现：
  - 路线地图
  - 遭遇
  - 奖励候选
  - 商店内容
- 地图、奖励、商店和战斗分别使用独立 RNG 流。
- 各随机流由统一 Run Seed 派生，避免某系统多调用一次随机数后改变整轮结果。
- 所有候选结果必须进入存档，而不是每次打开界面重新生成。

建议随机流：

```text
map_rng
encounter_rng
reward_rng
shop_rng
event_rng
battle_rng
sacrifice_rng
```

## 14. 存档与 Continue

### 14.1 存档策略

- 只允许一个活动 Run。
- 每个节点与关键选择后自动存档。
- 已有活动 Run 时点击 New Journey，弹窗确认覆盖。
- Continue 恢复当前活动 Run。
- 战斗中退出不保存中盘，重新进入后恢复到该战斗的战前部署阶段。
- 遭遇、奖励和 Seed 状态保持不变。

### 14.2 存档版本

- 存档包含明确版本号。
- 不兼容时安全作废活动 Run，并提示玩家。
- 图鉴和无尽模式解锁属于局外数据，应尽量保留。
- 开发期不要求为每个内部版本实现完整 Run 存档迁移。

### 14.3 建议 RunState 内容

```text
run_version
mode
seed
rng_stream_states
current_map_id
current_node_id
visited_node_ids
```

## 16. 教学、难度、本地化与平台

### 16.1 教学

- 使用首轮渐进式引导。
- 在真实 Run 中依次解释选秀、路线、部署、奖励、融合和共享槽位。

### 16.2 难度

- 新手应在数轮内完成常规 Run。
- 三次失败机制与简单 AI 用于降低挫败。
- 未来可加入挑战等级，但首版只预留难度修正器。

- 特殊移动、被动、遗物和 Boss 目标使用长按/点击详情。
- 战斗中提供简洁日志，记录：
  - 移动
  - 吃子
  - 被动触发
  - 道具使用
  - 终局原因

### 16.4 本地化

- 正式首版目标支持简体中文与英文。
- 所有数据内容使用本地化 Key，不直接把显示文本作为 ID。

### 16.5 平台

- 手机竖屏优先。
- 延续当前 360×640 逻辑尺寸。
- 目标设备为近五年主流手机。
- 触屏交互优先，同时保留未来键盘/鼠标适配空间。

## 26. 2.5D 棋盘与打击动画方向（2026-11-17 修订）

本节覆盖前文中与之冲突的表现层约束。规则层、RunState、事务存档和 BattleEvent 接口保持不变。

### 26.1 已确认的方向

1. **优秀的棋子移动与击杀动画是表现层第一优先级。**
2. 战斗棋盘使用 **2.5D 倾斜视角**：规则仍是普通方格，画面是带透视和厚度的倾斜棋盘；棋子是按远近排序的站立图。不使用等距 45° 菱形棋盘，不使用真 3D。
3. 不做逐帧手绘动画。所有演出由代码对静态棋子图完成：蓄力压扁、跳跃/冲刺、残影、命中停顿、震屏、推镜、切割、碎裂、烟尘、地面裂纹。
4. 攻击演出属于攻击方，受击演出属于受击方，两者在“命中”一刻对接。
5. 特殊棋子（非标准六种）暂不做专属演出，`strike_type = NONE`，使用简单移动。

### 26.2 六种标准棋子的攻击

| 棋子 | 攻击演出 | 打击类型 | 体型 |
|---|---|---|---|
| 兵 | 头槌：缩身、斜跳、前倾撞击 | 冲击 | 轻 |
| 马 | L 形腾跃踏击：人立蓄力，空中先走长边再折向，目标上方顿一下后踩落 | 重压 | 中 |
| 象 | 居合斩：蓄力发亮，斜线闪身穿过目标并留残影，停在目标侧后方，随后刀光出现 | 斩击 | 中 |
| 车 | 冲撞：后退蓄力、塔身震动冒烟，加速直冲 | 冲击 | 重 |
| 后 | 光枪贯穿：原地浮起，凝出光枪，后拉蓄力后射出贯穿目标，随后滑入格子 | 穿刺 | 重 |
| 王 | 王权裁决：原地亮起金光，瞄准光线后金色光柱从天而降，随后两步走入格子 | 重压 | 重 |

### 26.3 受击规则表（打击类型 × 受击方体型）

| 打击类型 | 轻 | 中 | 重 |
|---|---|---|---|
| 斩击 | 粉碎飘散 | 顺刀光角度斜切两半 | 斜切两半（更沉） |
| 冲击（攻击方重于受击方） | 高飞击飞 | 低平撞飞、落地翻滚滑行 | —（同级见下行） |
| 冲击（同级） | 击飞 | 快速翻倒 | 拦腰碎裂 |
| 冲击（攻击方轻于受击方） | — | 快速翻倒 | 先撬掉底座一块、再第二次撞倒 |
| 穿刺 | 贯穿击退 | 穿孔、裂纹蔓延后碎裂 | 同左，更慢 |
| 重压 | 压扁 | 自上而下压塌 | 沉入棋盘 |

补充规则：

- 命中停顿结束后的第一帧，受击方必须有明显位移或倾斜；蓄力只属于攻击方。
- 攻击方体型小于受击方时，重压类动画减速（更吃力）。
- 斜切类要保证看得清：切口与刀光同角度，两半先拉开并定格，命中时推镜、其他棋子变暗并半透明，攻击方不挡在受击方前面。
- Boss 或传说级棋子可以单独写专属受击演出，不受本表约束。

- `BoardProjection`：格子坐标与屏幕坐标的双向换算。
- `BattleBoardView`：代码绘制的倾斜棋盘、站立棋子、点击判定和移动演出。

### 27.9 实现说明（2026-11-18）

规则全部做成通用能力，写在棋子数据上（`resources/content/pieces/*.tres`），代码不按棋子 id 写特例：

| 能力 | 数据字段 / 规则 | 用到的棋子 |
|---|---|---|
| 只能往前 | `SlideMovementRule.relative_to_color` | 先锋、侍从 1 级 |
| 远程原地吃子 | `SlideMovementRule.ranged` | 鹰隼猎手、游侠、石像守卫、天鹰射手、爆破投石车 |
| 沿外圈滑行 | `EdgeSlideMovementRule` | 游侠 |
| 限距瞬移 | `RangeTeleportMovementRule`（同色格 / 只去安全格 / 每场一次） | 日月僧侣、隐王 |
| 照搬上一步 | `MimicLastMoveMovementRule` | 回声、千面者 |
| 学来的走法 | `LearnedMovesMovementRule` + `learn_capacity` | 变色龙、千面者 |
| 与王换位 | `SwapWithKingMovementRule`（每场一次） | 替身 |
| 被吃爆炸 | `explodes_when_captured` | 火药桶兵 |
| 被吃护盾 | `shields_allies_when_captured` | 殉道者 |
| 邻格免定身 | `protects_adjacent_from_immobilization` | 提灯人 |
| 外壳 | `shell_hits`（每场恢复） | 石像守卫 1、石巨人 2 |
| 复活 | `revive_after_turns`（每场一次） | 余烬鸟 2、炎凰 1 |
| 成长 / 进化 | `evolve_at_captures` + `evolves_into` | 侍从各级、水晶法师 |
| 交替形态 | `alternate_form_id` / `base_form_id` | 潮汐骑士 |
| 非兵升变 | `promotes_to` | 先锋 → 枪骑兵 |
| 一回合两次行动 | `extra_move_always`（刺客为 `extra_move_on_capture`） | 疾风信使、刺客 |
| 溅射 | `splash_on_ranged_capture` | 爆破投石车 |
| 破将死 | `survives_checkmate_once` | 护盾王 |

定下的细节：
- 第二次行动只能由获得它的那枚棋子使用；玩家可以点「End Turn」放弃。一回合最多两次行动。
- 护盾持续到对手的下一个回合结束。
- 爆炸和溅射也会被外壳挡下一次。
- 复活：余烬鸟错过己方 2 个回合，在第 3 个回合开始时回到起始格；炎凰错过 1 个。起始格被占时，从己方底线左角开始逐行找第一个空格。
- 只有打赢的战斗，侍从等级、变色龙学到的走法和水晶法师的进化才会保留到整局 run（存在 `PieceInstanceState`）。
- 千面者由变色龙融合而来时继承它学会的走法，超过 3 种时丢掉最早的。

打击演出在 `scripts/battle/strike/NewPieceStrikes.gd`（由 `StrikeDirector` 调用）。截帧检查工具：`scripts/visual_review/capture_new_strikes.gd`（需要非 headless 运行）。
