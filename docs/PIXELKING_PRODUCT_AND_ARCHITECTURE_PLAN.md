## 1. 产品核心定位

PixelKing 是一款手机竖屏优先、以短局为主的像素风国际象棋 Roguelike。

核心体验优先级已经确定为：

1. **融合构筑是第一核心。**
2. 棋盘战术为构筑提供验证场景。
3. 路线选择、奖励、商店、事件和遗物共同提供风险收益抉择。
4. AI 暂时保持简单贪心，不追求高强度棋力；目标是让玩家体验构筑，而不是被强 AI 压制。

目标常规 Run 时长为 **20–30 分钟**。玩家应当在数轮尝试内有较高机会完成首次通关，而不是面对高难度棋类挑战。

未来可以加入递增挑战等级，但不进入首个纵切版本。长期挑战主要先由无尽模式承担。

## 2. 已确认的完整游戏流程

### 2.1 主流程

点击 `New Journey` 后，不再直接进入当前战斗场景，而是进入以下流程：

```text
New Journey
  ↓
如已有活动 Run：确认是否覆盖
  ↓
输入或随机生成 Run Seed
  ↓
三轮开局三选一选秀
  ↓
生成纵向分叉路线地图
  ↓
选择节点
  ↓
非战斗整备 / 战前自由部署
  ↓
战斗
  ↓
奖励三选一 / 商店 / 事件 / 休息
  ↓
返回路线地图并进入下一层
  ↓
最终 Boss
  ↓
Run 结算、图鉴更新、解锁无尽模式
```

### 2.2 首个可玩里程碑

首个验收目标不是只做一张路线选择页面，而是使用占位内容打通一轮完整 Run：

- 三轮选秀
- 路线地图
- 战前部署
- 普通战斗
- 奖励
- 战败牺牲与重试
- 商店、事件、休息的最小占位实现
- 精英节点
- 最终 Boss
- Run 结算
- Continue 自动存档恢复

系统优先，允许使用文本、色块、现有素材和占位数据。美术精修不阻塞流程验证。

## 3. 常规 Run 与无尽模式

### 3.1 常规 Run

- 单区域，约 **6–8 层**。
- 每层通常提供 **2–3 个可选节点**。
- 使用固定骨架、随机节点内容的纵向分叉地图。
- 玩家从地图底部向上推进，节点选择后不能回退。
- 地图信息完整公开，玩家可提前看到节点类型、敌人倾向和奖励类别。
- 地图至少保证：
  - 1 个精英节点
  - 1 个商店
  - 1 个休息节点
  - 最终 Boss
- 普通战斗与随机事件填充其余节点。

### 3.2 无尽模式

- 初始锁定。
- 首次完成常规 Run 后解锁。
- 无尽模式是独立新 Run，重新进行三轮开局选秀，不继承最近通关阵容。
- 核心目标是检验阵容与融合构筑能够坚持多少关。
- 敌人持续增强。
- 首版无需同时实现复杂排行榜，但 Seed 与确定性架构应为未来挑战模式预留基础。

## 4. 路线节点设计

首版节点类型全部需要在数据层预留：

1. **普通战斗**
   - 主要推进节点。
   - 胜利后提供基础金币和三选一奖励。

2. **精英战斗**
   - 更高风险。
   - 是遗物的重要来源之一。
   - 奖励稀有度高于普通战斗。

3. **商店**
   - 使用战斗和节点奖励获得的金币。
   - 支持付费刷新。
   - 可出售：
	 - 棋子
	 - 当前阵容满足条件的融合图纸
	 - 一次性道具
	 - 棋子保护/移除服务
	 - 休息类服务
   - 玩家只能在商店主动出售已有棋子、遗物或道具。

4. **随机事件**
   - 风格以风险收益抉择为主。
   - 使用短文本包装机制选择。
   - 可以影响金币、棋子、失败机会、遗物、道具或路线状态。

5. **休息/修整**
   - 每次提供三选一服务。
   - 服务池可包括：恢复、保护、金币或其他整备效果。
   - “保护棋子”默认抵消下一次牺牲：受保护棋不进入下一次战败候选，触发后保护消失。

6. **Boss**
   - 路线终点。
   - 使用特殊棋盘或特殊目标。
   - 击败后立即结算常规 Run。

## 5. 开局选秀与稀有度

### 5.1 开局选秀

- 每个新 Run 从标准国王开始。
- 连续进行 **3 轮三选一**。
- 每轮选择一枚棋子，全部加入初始构筑。
- 每轮至少保证一枚 **稀有或更高** 的强力棋子。
- 开局选秀池只出现普通与稀有基础棋：
  - 不出现融合产物。
  - 史诗与传说留给路线成长。
- 每次 Run 的初始构筑应不同。

### 5.2 稀有度

采用四档稀有度：

1. 普通
2. 稀有
3. 史诗
4. 传说

稀有度用于统一影响：

- 棋子基础强度
- 奖励池
- 商店价格
- 节点掉落
- 图鉴表现
- 融合产物定位

奖励稀有度主要由 **节点类型与路线层数** 决定。越后期、精英和 Boss 的奖励池越好。

## 6. 阵容、仓库与部署

### 6.1 容量

- 可上场的非国王棋子容量：**5**。
- 国王不占上述 5 个挑战者上场位，并且必须上场；因此完整阵容最多为“国王 + 5 枚非王棋”。
- 仓库容量：**5**。
- 上场与仓库分离。
- 所有非战斗界面都可以打开阵容管理，调整上场与仓库。

### 6.2 获得棋子

- 普通棋子奖励默认进入仓库。
- 仓库已满时，玩家必须当场替换一枚已有棋子或放弃新棋。
- 不能依靠无限候补区规避容量限制。

### 6.3 战前部署

- 每场战斗前进入部署阶段。
- 玩家可以在己方两行内自由部署上场棋子。
- 国王也可以放置在己方两行任意合法格。
- 玩家可以完整看到敌方阵容与初始位置，再决定自己的部署。
- 玩家默认先手，但遗物未来可以改变先手规则。
- 普通战首版固定使用 5×5 棋盘。
- Boss 可以使用特殊棋盘尺寸或格子规则。

## 7. 战斗胜负、战败与重试

### 7.1 普通与精英战胜利

- 普通战和精英战继续采用快速终局规则：**敌方只剩国王时玩家获胜**。
- 不要求把残局继续走到标准将死。
- 当前自定义王车易位继续保留：国王与未移动的己方车交换位置；这不是标准国际象棋易位。

### 7.2 Boss 胜利目标

Boss 允许覆盖普通胜利目标。

每个 Boss 通常组合 1–2 种机制，而不是要求单个 Boss 包含全部机制：

- 多阶段
- 击破部件
- 限定回合击杀
- 占领关键格

Boss 目标、阶段和特殊棋盘应数据驱动；复杂 Boss 可以通过专属目标脚本扩展。

### 7.3 三次战败规则

- 整轮 Run 累计最多失败 3 次。
- 第 1、2 次战败：进入三选一牺牲流程，然后重试同一遭遇。
- 第 3 次战败：Run 直接结束，不再进行无意义的牺牲选择。
- 如果战败时没有可牺牲的非国王棋子，即使还未达到第三次，Run 也直接结束。

### 7.4 牺牲流程

- 候选池来自玩家拥有的全部非国王棋子，包括上场与仓库。
- 融合棋也可能成为牺牲候选。
- 系统随机提供三枚候选，玩家选择牺牲其中一枚。
- 受到保护的棋子不进入下一次候选池。
- 牺牲后：
  - 敌我战斗局面完全重置。
  - 敌方恢复同一遭遇模板。
  - 玩家使用损失后的阵容重新部署。
  - 同一遭遇的奖励不会因为失败而降级。

## 8. 融合系统

融合构筑是项目的第一核心系统。

### 8.1 固定配方

- 融合采用预先设计的固定配方。
- 配方示例：A + B + C → X。
- 玩家必须实际拥有配方所需的全部素材，配方图纸才允许进入掉落池或商店。
- 如果玩家只有 A 和 B，则要求 A+B+C 的图纸不能出现。
- 素材中的同类型实例在首版完全等价，不考虑实例强化差异。

### 8.2 融合执行

- 图纸出现在奖励三选一或商店中。
- 玩家选中图纸后，先显示完整预览：
  - 将消耗哪些棋子
  - 生成什么融合棋
  - 产物走法、被动与稀有度
  - 阵容和容量变化
- 玩家确认后：
  - 所有素材被消耗。
  - 生成一枚独立融合棋。
  - 融合棋默认进入仓库，之后重新编队。
- 玩家取消确认时返回原三选一，仍可选择其他奖励。
- 商店图纸使用同一套预览、确认与自动融合流程；确认后才扣除金币。

### 8.3 多级融合

- 融合产物可以继续作为更高阶配方的素材。
- 形成明确的融合树。
- 每个融合产物都是预先设计好的独立 `PieceDef`：
  - 稳定 ID
  - 专属名称
  - 专属美术
  - 稀有度
  - 移动规则
  - 被动能力

### 8.4 国王融合

- 初始始终是标准国王。
- 国王可以参与固定配方融合。
- 王融合产物必须继承唯一的 `King` 身份与失败条件。
- 原国王与素材被消耗，产物成为新的唯一追踪国王。
- 王融合产物强制处于上场阵容。
- 王融合后仍使用统一的将军与失败规则。
- 融合王可以继续参与更高阶王融合。
- 合格的王融合图纸与普通图纸一样进入随机奖励池，但可以设置更高稀有度。

## 9. 奖励、金币与商店

### 9.1 战斗奖励

- 战斗胜利后主要使用三选一奖励。
- 候选可包含：
  - 棋子
  - 当前满足条件的融合图纸
  - 金币
  - 道具
  - 遗物（根据节点来源决定）
- 金币主要来自节点奖励与事件，不依赖战斗中的吃子数。

### 9.2 商店

- 使用金币购买。
- 支持付费刷新。
- 商品生成必须使用独立 RNG 流并保存候选，防止退出游戏刷新商品。
- 玩家可以在商店出售已有内容。
- 融合图纸必须经过资格过滤，只展示当前阵容可立即融合的配方。

### 9.3 事务式选择

为了防止通过强退刷奖励：

1. 先根据 Seed 生成并保存奖励、事件或商店候选。
2. 再展示给玩家。
3. 玩家提交选择后，以事务形式更新 RunState 并保存。

## 10. 遗物与一次性道具

### 10.1 共享六槽

- 遗物和一次性道具共用 **6 个挑战者槽位**。
- 这与当前工程中 persistent/consumable 共用栏位的方向一致。
- 遗物永久占据槽位，直到玩家主动替换或移除。
- 一次性道具使用后消失并释放槽位。
- 满槽获得新内容时，玩家选择替换已有内容或放弃新内容。
- 被替换的遗物永久销毁，不自动返还金币。

### 10.2 遗物

- 首个纵切也需要完整的遗物系统，而不是完全延期。
- 首批遗物以改变战斗规则为主。
- 遗物来源包括精英、Boss、商店和事件，不同来源可使用不同池。
- 相同遗物不可重复获得，已拥有遗物从候选池移除。
- 遗物与棋子被动共用统一战斗事件与效果队列。

### 10.3 一次性道具

- 在己方走棋前使用。
- 每回合最多使用一个。
- 使用道具不消耗本回合正常走棋机会。
- 道具效果也通过统一命令/事件管线执行。

## 11. 特殊棋子、被动与效果队列

### 11.1 能力方向

特殊棋子以被动能力为主，但效果系统必须具备足够通用性，允许未来能力：

- 移动或交换其他棋子
- 召唤或复制棋子
- 改变格子状态
- 修改移动规则
- 在移动前后触发
- 在吃子与被吃时触发
- 在回合开始/结束触发
- 在将军或濒死状态触发
- 提供邻接或站位持续效果

### 11.2 基础行动经济

- 仍保持一回合移动一枚棋子一次。
- 道具是走棋前的额外操作。
- 首版不引入多行动点系统。

### 11.3 效果结算

战斗阶段建议明确拆分为：

```text
部署
→ 玩家道具窗口
→ 玩家走棋
→ 效果队列结算
→ 敌方行动
→ 效果队列结算
→ 终局检查
```

结算规则：

1. 当前行动方的触发优先。
2. 同方效果按以下顺序稳定排序：
   - 效果优先级
   - 棋盘位置
   - 实例 ID
3. 允许完整死亡连锁。
4. 必须提供防无限循环机制，例如最大事件数、同来源重复保护或明确错误终止。
5. 整个效果队列结算完成后，再检查将军、孤王和胜负。

### 11.4 统一 BattleEvent

每次行动应生成一串稳定、可记录的 `BattleEvent`，由不同系统共同消费：

- 规则状态更新
- 动画播放器
- 简洁战斗日志
- 自动化测试
- 未来回放与 Bug 复现

动画与逻辑必须分离：

- 逻辑先生成确定性事件序列。
- 表现层逐个播放事件。
- 玩家可以加速播放。
- UI 动画不能反向决定规则结果。

## 12. AI 与敌方遭遇

- 当前贪心 AI 暂时保留。
- 不实现 Minimax，避免敌人过强。
- 后续只修复明显错误或让 AI 理解新增合法行动，不主动大幅提高棋力。
- 敌方强度使用分层遭遇模板：每一层从对应强度池中抽取敌方阵容。
- 普通战以模板为主，不根据玩家战力进行强制动态追平。
- AI 同分决策若参与可复现要求，应从战斗独立 RNG 流中选择。

---

## 13. Seed、随机流与可复现性

- 玩家可以查看并手动输入 Run Seed。
- 相同 Seed 至少必须复现：
  - 路线地图
  - 遭遇
  - 奖励候选
  - 商店内容
- 地图、奖励、商店和战斗分别使用独立 RNG 流。
- 各随机流由统一 Run Seed 派生，避免某系统多调用一次随机数后改变整轮结果。
- 所有候选结果必须进入存档，而不是每次打开界面重新生成。

建议随机流：

```text
map_rng
encounter_rng
reward_rng
shop_rng
event_rng
battle_rng
sacrifice_rng
```

## 14. 存档与 Continue

### 14.1 存档策略

- 只允许一个活动 Run。
- 每个节点与关键选择后自动存档。
- 已有活动 Run 时点击 New Journey，弹窗确认覆盖。
- Continue 恢复当前活动 Run。
- 战斗中退出不保存中盘，重新进入后恢复到该战斗的战前部署阶段。
- 遭遇、奖励和 Seed 状态保持不变。

### 14.2 存档版本

- 存档包含明确版本号。
- 不兼容时安全作废活动 Run，并提示玩家。
- 图鉴和无尽模式解锁属于局外数据，应尽量保留。
- 开发期不要求为每个内部版本实现完整 Run 存档迁移。

### 14.3 建议 RunState 内容

```text
run_version
mode
seed
rng_stream_states
current_map_id
current_node_id
visited_node_ids
resolved_node_payloads
failed_battles
remaining_failure_allowance
player_roster
active_piece_ids
reserve_piece_ids
challenger_slots
owned_recipe_history
gold
protected_piece_ids
current_encounter_id
current_encounter_seed
pending_choice
run_statistics
```

## 15. 局外解锁与图鉴

### 15.1 常规 Run 通关

击败最终 Boss 后立即进入结算页，记录：

- Seed
- 选择路线
- 最终阵容
- 完成的融合
- 遗物与道具
- Boss 结果

首次通关解锁无尽模式。

### 15.2 图鉴

首版图鉴范围：

- 棋子
- 融合配方
- 遗物
- Boss

内容在常规 Run 中遇到后解锁。未知条目可以使用剪影。

所有棋子从系统角度都存在于常规 Run 内容池中，不通过永久数值成长解锁；玩家只是未必能在一次 Run 中随机遇到。

首版局外成长只包含：

- 图鉴记录
- 无尽模式解锁

不包含永久数值加成。

## 16. 教学、难度、本地化与平台

### 16.1 教学

- 使用首轮渐进式引导。
- 在真实 Run 中依次解释选秀、路线、部署、奖励、融合和共享槽位。
- 避免一开始提供过长的独立教程。

### 16.2 难度

- 新手应在数轮内完成常规 Run。
- 三次失败机制与简单 AI 用于降低挫败。
- 未来可加入挑战等级，但首版只预留难度修正器。

### 16.3 信息展示

- 特殊移动、被动、遗物和 Boss 目标使用长按/点击详情。
- 战斗中提供简洁日志，记录：
  - 移动
  - 吃子
  - 被动触发
  - 道具使用
  - 终局原因

### 16.4 本地化

- 正式首版目标支持简体中文与英文。
- 所有数据内容使用本地化 Key，不直接把显示文本作为 ID。

### 16.5 平台

- 手机竖屏优先。
- 延续当前 360×640 逻辑尺寸。
- 目标设备为近五年主流手机。
- 触屏交互优先，同时保留未来键盘/鼠标适配空间。

## 20. 分阶段行动计划

### 阶段 A：数据基础与 RunState

> **当前进度：核心基础已完成。** 已实现 RunState、Run 内棋子实例、七路独立 RNG、活动 Run 原子保存、损坏/版本不兼容存档失效、RunManager autoload 以及对应测试。节点事务保存将在阶段 C 接入实际地图节点时完成；局外存档文件将在首次实现图鉴/无尽解锁时创建。

1. 定义稳定 ID 约定。
2. 创建 RunState、存档版本和序列化。
3. 建立独立 RNG 流。
4. 将活动 Run 与局外数据分开保存。
5. 为保存、加载、覆盖和不兼容版本编写测试。

**验收：** 相同 Seed 创建相同空白 Run；节点后保存并可恢复；旧版本安全作废。

### 阶段 B：三轮开局选秀

**实施状态：已完成。** 数据规则、事务式存档、竖屏选秀场景、主菜单 New/Continue/覆盖确认和自动化测试均已落地。

1. 创建选秀资源池和稀有度。
2. 三轮三选一。
3. 每轮至少一枚稀有棋。
4. 选择结果进入仓库/阵容状态。
5. 候选在显示前事务式存档。

**验收：** 相同 Seed 和选择生成相同初始阵容；刷新页面不能改变候选。

### 阶段 C：PK-02 路线地图

**实施状态：已完成。** 已实现 Resource 驱动的节点/模板、确定性 6–8 层分支图、必需节点保底、路线锁定与事务保存、竖屏地图界面、占位非战斗节点推进，以及原型战斗胜利后返回地图。

1. 固定骨架+随机节点生成。
2. 6–8 层、每层 2–3 节点。
3. 保证精英、商店、休息和 Boss。
4. 节点信息完整公开。
5. 选择后锁定路线并自动保存。
6. 战斗节点暂时接入当前战斗。

**验收：** New Journey 不再直接进入战斗；可以从选秀进入地图并选择节点。

### 阶段 D：阵容管理与部署

1. 国王固定上场，另有 5 个非王上场位与 5 个仓库位。
2. 所有非战斗界面可进入阵容管理。
3. 战前显示敌人并自由部署己方两行。
4. 国王合法性检查。
5. 战斗中退出恢复战前部署。

**验收：** 玩家可以带不同初始构筑进入同一遭遇，并保存部署前状态。

### 阶段 E：BattleController 小步拆分

1. 先抽离设置面板。
2. 抽离 ChallengerTray。
3. 抽离 BattleBoardView。
4. 抽离 HUD 与结果面板。

1. BattleAction 与 CommandProcessor。
2. 统一 BattleEvent。
3. BattleEffectQueue 和稳定排序。
4. 死亡连锁与循环保护。
5. 动画播放器与战斗日志。
6. 道具窗口和每回合一次限制。

**验收：** 六槽替换逻辑正确；相同 Seed 商店内容一致；重复遗物被过滤。
